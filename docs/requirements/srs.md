### Non-Functional Requirements

| **ID** | **Category**                         | **Requirement (measurable)**                                                                                                                                                                                                                                                                                                                                                                                                                                    | **How it will be verified**                                                                                                                                                                                                |
| ------ | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NFR-01 | Performance                          | The system shall return authenticated course-list, material-list, and assignment-list API responses within 2 seconds at P95, with fewer than 1% unexpected server errors, during a 10-minute run after a 1-minute warm-up. Proposed workload: 50 concurrent users, 20 courses, 500 enrollments, 200 material records, and 200 assignments; one request per user every 5 seconds, evenly distributed across the three endpoints. File transfer time is excluded. | Run a load test against the deployment candidate from a fixed test runner; record its location, network latency, dataset, P95 by endpoint, and server-error rate.                                                          |
| NFR-02 | Security - authorization             | The system shall enforce authentication, role, course ownership, and enrollment checks on the server for all protected Must-have operations. Every unauthorized request in the access-control test matrix shall disclose no protected course/submission data and cause no mutation. Hiding UI controls alone shall not grant or restrict access.                                                                                                                | Exercise APIs and file-download access as an unauthenticated user, enrolled student, non-enrolled student, course owner, and another teacher. All prohibited combinations must be denied; verify stored data is unchanged. |
| NFR-03 | Usability                            | At least 4 of 5 first-time student test participants shall independently join a course, locate its material, and submit a valid assignment file within 5 minutes in total using a provided account, valid invitation, and prepared file, excluding sign-in time.                                                                                                                                                                                                | Run a moderated task-based test with the same instructions and dataset; record completion time, success, and any assistance. This is a proposed test, not a completed user study.                                          |
| NFR-04 | Accessibility                        | All controls needed for registration, login, joining a course, accessing materials, and submitting an assignment shall be operable by keyboard, with a visible focus indicator. Each input shall have a programmatic label, and validation errors shall identify the affected input.                                                                                                                                                                            | Perform the five workflows using keyboard only; inspect labels and error associations using browser accessibility tools. No inaccessible control may block a Must-have workflow.                                           |
| NFR-05 | Compatibility and layout             | All Must-have acceptance scenarios shall pass on the stable versions of Chrome, Edge, and Firefox available at the test baseline. At viewport widths of 360 and 1366 CSS pixels, primary controls shall remain reachable and readable; wide tables may scroll within their own container.                                                                                                                                                                       | Record exact browser versions and run the scenarios at both widths. Inspect for clipped controls, page-level horizontal scrolling, and overlapping text.                                                                   |
| NFR-06 | Reliability and data integrity       | The system shall report a submission as successful only after its file and submission record are persistently stored. Across 10 injected interruption/failure trials during upload or save, no incomplete submission shall be shown as successful and any previously accepted submission shall remain accessible.                                                                                                                                               | Interrupt uploads and simulate storage/database failures in a test environment; inspect the user message, stored file, submission record, and previous accepted submission after each trial.                               |
| NFR-07 | Security - transport and credentials | The deployed application shall use HTTPS for authentication and protected data/file access. For credential-based authentication, passwords shall not appear in plaintext in persistent storage, application logs, or API responses.                                                                                                                                                                                                                             | Inspect deployed requests, a test-account database record, application logs, and API responses; verify secure transport and review the password-storage implementation.                                                    |
| NFR-08 | Upload validation                    | The system shall enforce BR-06 file type and size limits on the server for material and assignment uploads. It shall reject every invalid file in the boundary/type test set with a clear error and shall not publish the rejected file as a material or successful submission.                                                                                                                                                                                 | Test an allowed file, an empty file, exactly 20 MiB, 20 MiB plus one byte, a disallowed type, and a file whose extension conflicts with its validated content type.                                                        |

### Domain Requirements and Business Rules

| **ID** | **Rule**                                                                                                                           | **Source (policy, law, standard)** |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| BR-01  | Each user has exactly one role: Student or Teacher.                                                                                | FR-01C                             |
| BR-02  | A teacher can create and manage many courses, but each course belongs to only one teacher.                                         | FR-02A, FR-02B                     |
| BR-03  | A student can join many courses via invite code or link, and a course can have many students without duplicates.                   | FR-03A, FR-03C                     |
| BR-04  | Only the course teacher and enrolled students can access the course's materials, assignments, announcements, and discussions.      | FR-03B, NFR-02                     |
| BR-05  | A course can have many materials, and enrolled students can only view or download published materials.                             | FR-04A, FR-04B                     |
| BR-06  | Uploaded files (materials and submissions) must not be empty, must be at most 20 MiB, and must have an allowed file type.          | FR-04A, FR-05B, NFR-08             |
| BR-07  | Each assignment must have a due date, and any submission made after the due date is flagged as late.                               | FR-05A, FR-05B, FR-05C             |
| BR-08  | Only the course teacher can grade submissions and post announcements, while both the teacher and students can chat in discussions. | FR-06A, FR-07A, FR-07B             |

### Acceptance Criteria

| **Feature** | **Given**                                                            | **When**                                                                        | **Then form**                                                                                           |
| ----------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| F01         | A user is not logged in.                                             | They submit valid credentials.                                                  | The system authenticates them and authorizes access according to their assigned role.                   |
| F02         | A teacher is logged in.                                              | They create a course with valid details, or update or delete a course they own. | The system creates, updates, or deletes the course as requested.                                        |
| F03         | A logged-in student has a valid course invite code or link.          | They use it to join the course.                                                 | The system enrolls them and adds them to the course’s roster after the teacher of that course confirms. |
| F04         | A teacher owns a course.                                             | They publish valid course material.                                             | The system makes the material available for enrolled students to view or download.                      |
| F05         | A student is enrolled in a course with an assignment and a deadline. | They submit a valid file for the assignment.                                    | The system saves the submission and flags it as late if submitted after the deadline.                   |
